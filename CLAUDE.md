# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

This is **Ghostgram Desktop** — a fork of Telegram Desktop (tdesktop) with extra client-side privacy/automation features. The upstream tdesktop conventions still apply: read `AGENTS.md` for repo-wide rules (coding style without comments, `_q` for QString literals, `auto` for type deduction, RPL pipelines, `tr::lng_*` for upstream localization, MTProto API patterns, `.style` files for sizes).

`AGENTS.md` was written for the upstream Windows/WSL setup. **This checkout is macOS Apple Silicon with Xcode.** Use the build commands below, not the ones in `AGENTS.md`.

## Working rules (from user feedback in past sessions)

- **Never run `cmake --build` / `xcodebuild` / `ninja` without an explicit user command** (the user types `билди` when they want a build). Diagnostics and edits are fine; build kicks are not.
- **No localization for Ghostgram-added strings.** Use raw `u"Something"_q` literals directly. Don't add entries to `lang.strings` for new Ghostgram features.
- The user has 24 GB RAM on Apple Silicon — debug builds are fine to run, full rebuilds take ~10–25 min, incremental ~1–5 min.

## Build (macOS, verified)

The Xcode project is generated by CMake into `out/`:

```bash

cd /Users/ichmagmaus/Desktop/ghostgram-pc/out && cmake .

# Build Debug:
xcodebuild -project /Users/ichmagmaus/Desktop/ghostgram-pc/out/Telegram.xcodeproj \
  -target Telegram -configuration Debug ONLY_ACTIVE_ARCH=YES

# Build Release (always pass -arch arm64; default tries x86_64+arm64 and breaks):
xcodebuild -project /Users/ichmagmaus/Desktop/ghostgram-pc/out/Telegram.xcodeproj \
  -target Telegram -configuration Release ONLY_ACTIVE_ARCH=YES -arch arm64
```

Run output is in **`out/Debug/Ghostgram.app`** or **`out/Release/Ghostgram.app`** (not `Telegram.app` — an old stale bundle from before the rebrand may still be there; ignore it). API credentials are loaded from `~/.ghostgram-pc/api.env` (chmod 600, NEVER put values in memory or git).

The `xcodeproj` is fully generated — **never edit it through Xcode's project navigator** (adding files, changing build settings). If you see clangd diagnostics like `'base/timer.h' file not found` or `Use of undeclared identifier 'crl'`, those are LSP phantoms — clangd doesn't see CMake include paths. **Trust the real `xcodebuild` output, not the LSP**.

## Ghostgram architecture

All fork-specific code lives under `Telegram/SourceFiles/ghostgram/` in namespace `Ghostgram`. Single entry point:

```cpp
Ghostgram::Manager::Instance().config()        // -> Config& (toggles, persisted JSON)
Ghostgram::Manager::Instance().ghostMode()     // -> GhostMode& (online/typing/read suppression logic)
Ghostgram::Manager::Instance().archive()       // -> MessageArchive& (deleted + edited)
Ghostgram::Manager::Instance().mediaArchive() // -> MediaArchive& (ephemeral / view-once)
```

Modules:

- `ghostgram_config.{h,cpp}` — singleton-flavor `Config` with every toggle (`ghostMode`, `hideOnline`, `saveDeletedMessages`, `bypassProtectedContent`, `blockAds`, `hideReactions`, `squareUserpics`, `fakePremium`, `fakeStars` + amount, `eternalOnline`, `ghostSendDelay` + text/media seconds, `antiCaps`, `autoFormat` enum, `customFontPath/Family`, `translateOutgoing` + target lang, `archiveOpacity`, ...). All persisted to `tdata/ghostgram_config.json` via debounced `base::Timer` (500ms). Each field has `getter()`, `setValue(v)`, and `rpl::producer<T> valueValue()`.
- `ghostgram.{h,cpp}` — `Manager` singleton wiring the above.
- `ghost_mode/` — `GhostMode` with `shouldHideOnline()`, `shouldForceOffline()`, `shouldSuppressReadHistory()`, `shouldSuppressReadStories()`, `shouldSuppressTyping()`, plus a thread-local `ActionScope` RAII counter for "user just took an action" overrides.
- `message_archive/` — `MessageArchive` owns `DeletedMessages` and `EditedMessages` flat_maps, JSON-persisted to `tdata/ghostgram_archive.json`. `DeletedMessages::find/contains` and `EditedMessages::hasEdits/historyFor/previousText` are used by UI hooks.
- `media_archive/` — `MediaArchive` for view-once photos/videos and voice/round notes. Copies files into `tdata/ghostgram_media/` on save; metadata in `tdata/ghostgram_media_archive.json`.
- `edit_history_box.{h,cpp}` — `Ui::GenericBox` builder showing all known versions of an edited message.
- `deleted_reply.{h,cpp}` — `TryQuoteDeletedInto(InputField, item)` inserts a blockquote of a deleted message's author + text into the composer when the user hits Reply on a deleted item.
- `outgoing_text.{h,cpp}` — `ApplyOutgoingTextHooks(TextWithTags&)` applies the gtranslate → anti-caps → auto-format pipeline before any outgoing message leaves the client.
- `gtranslate.{h,cpp}` — `TranslateSync(text, lang, timeoutMs)` synchronous HTTP call to `translate.googleapis.com/translate_a/single` (no API key, client=gtx), parses JSON response. Blocking via `QEventLoop` + `QTimer`. Falls back to original text on any error.
- `read_up_to.{h,cpp}` — `ReadUpTo(item)` directly sends `MTPchannels_ReadHistory` / `MTPmessages_ReadHistory`, bypassing `Histories::sendReadRequest` (which is intercepted by ghost mode).

## How features integrate into upstream tdesktop

The pattern is: **find the upstream code path, branch on `Ghostgram::Manager::Instance().config().xxx()`**. There is no separate event bus or DI layer — features are hooks directly in upstream files. Be careful to add `#include "ghostgram/ghostgram.h"` AND `#include "ghostgram/ghostgram_config.h"` whenever you reference `Manager::Instance().config().xxx()` — the Config class is forward-declared in `ghostgram.h` and is incomplete without the second include.

Examples of where hooks live (so you don't grep the world):

- `apiwrap.cpp::sendMessage` — outgoing text transforms (`ApplyOutgoingTextHooks`), bypass-protected forward (loops items as `SendExistingDocument/Photo/sendMessage` instead of `MTPmessages_ForwardMessages`), and ghost send-delay (sets `message.action.options.scheduled = unixtime + N` so Telegram serverside-schedules the message).
- `api/api_sending.cpp::SendExistingMedia` — same delay hook for media + caption transform.
- `api/api_updates.cpp::Updates::updateOnline` — `eternalOnline` overrides `lastNonIdleTime = crl::now()` and forces `isOnline = true`, so the existing tdesktop timer keeps re-asserting online via `account.updateStatus(offline=false)`. There is no separate ping timer.
- `data/data_session.cpp::updateEditedMessage` — captures previous text before `applyEdition` and calls `archive().notifyEdit`.
- `data/data_session.cpp::processMessagesDeleted/processNonChannelMessagesDeleted` — preserves deleted item locally via `requestItemViewRefresh + requestItemResize` instead of removing it.
- `data/data_peer.cpp::PeerData::allowsForwarding/paintUserpic/GenerateUserpicImage` — `bypassProtectedContent` and `squareUserpics` overrides.
- `data/data_user.cpp::UserData::isPremium` — returns `true` for self when `fakePremium` is on. Because `Session::premium()` reads `_user->isPremium()`, this propagates everywhere.
- `data/components/credits.cpp::Credits::balance/balanceValue/loaded` — return fake stars when `fakeStars` is on.
- `data/components/sponsored_messages.cpp::request/requestForVideo` — early-return when `blockAds` is on.
- `history/history_widget.cpp::HistoryWidget::replyToMessage` and `history/view/controls/history_view_compose_controls.cpp::ComposeControls::replyToMessage` — call `TryQuoteDeletedInto(_field, item)` if `!item->isRegular()` and the item is in the deleted archive.
- `history/view/history_view_message.cpp` — opacity for deleted items, trash + timer icons in `drawInfo`, lazy `recordFileSaved` for ephemeral media.
- `history/view/history_view_element.cpp::refreshReactions` — drops reactions when `hideReactions` is on.
- `history/history_item.cpp::repliesAreComments` — false when `hideComments` is on; also the `vttl_seconds` hook that zeroes ephemeral TTL and registers the message in `mediaArchive`.
- `history/view/history_view_context_menu.cpp` — forward-declared `AddGhostgramEditHistoryAction` and `AddGhostgramReadUpToAction`, both invoked from `AddTopMessageActions`. The "History" item appears whenever `item->Has<HistoryMessageEdited>()` OR there's a local archive entry; "Read to here" appears for any incoming non-service regular item.
- `ui/empty_userpic.cpp::GhostgramDrawShape` — switches `drawEllipse` → `drawRoundedRect` for Saved/Archive/HiddenAuthor avatars when `squareUserpics` is on.
- `ui/effects/outline_segments.cpp::PaintOutlineSegments` — `count==1` (single-segment story ring) drawn as rounded rect when `squareUserpics` is on. Multi-segment rings are a known limitation.
- `core/application.cpp::Application::run` — registers custom TTF via `QFontDatabase::addApplicationFont` and forwards to `style::SetCustomFont` before `StartFonts()`.

## Settings UI

All Ghostgram toggles live in `Telegram/SourceFiles/settings/sections/settings_ghostgram.cpp` (registered as section type `Settings::GhostgramId()`). When adding new toggles, copy the existing `AddToggle(container, u"Title"_q, config.xxxValue(), [](bool v) { ... })` pattern. For non-bool settings (int delays, language code, font path, stars amount), the pattern is a `SettingsButton` whose label is reactive `config.xxxValue() | rpl::map(...)` and whose click opens a `Ui::GenericBox` with an `InputField`.

Box dialogs that need `Ui::show(Box(...))` require `#include "boxes/abstract_box.h"`. Without it, you get `no member named 'show' in namespace 'Ui'`.

## Adding new Ghostgram modules

1. Create `Telegram/SourceFiles/ghostgram/<name>.{h,cpp}` (or subfolder).
2. Add both files to `Telegram/CMakeLists.txt` next to the existing `ghostgram/*.cpp/.h` entries (around line 1054–1080).
3. Run `cmake .` from `out/` to regenerate the Xcode project.
4. **Do not** add the files via Xcode's UI — they'll be wiped on the next CMake regen.

## What lives where, briefly

- **Local-only state** (never sent to TG): `tdata/ghostgram_config.json`, `tdata/ghostgram_archive.json`, `tdata/ghostgram_media_archive.json`, `tdata/ghostgram_media/`.
- **Server-visible behavior we modify**: online/typing/read status (suppressed or forced via eternalOnline), outgoing message body (translated, anti-caps'd, auto-formatted), forward bypass (sent as fresh messages from us), send-delay (Telegram-side `schedule_date`), `messages.readHistory` from "Read to here".
- **Pure UI fakes** (never touched by server): fakePremium, fakeStars, square avatars, archive opacity, custom font, hide reactions/comments, edit history box, deleted-message preservation in chat.

## Style nits specific to this fork

- When inserting Ghostgram hooks, **don't** add explanatory comments saying "Ghostgram: ...". The branch is self-evident from `Ghostgram::Manager::Instance().config().xxx()` showing up in the condition.
- Tags in `TextWithTags` use `Ui::InputField::kTagBold` / `kTagItalic` / `kTagBlockquote` / `kTagCode` / etc. (defined in `lib_ui/ui/widgets/fields/input_field.h`).
- For `crl::time` arithmetic involving seconds-to-ms, `crl::time(N) * 1000` is the idiom.
